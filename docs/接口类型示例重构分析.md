# 接口类型示例重构分析

## 背景

当前接口类型（Interface）的默认示例 `if_raw_material`（原材料），是在抽象父类建模概念引入之前创建的。现在 `raw_materials` 已作为抽象父类存在，其子类型通过继承关系已经实现了"归类为原材料"的目的。

## 问题

`if_raw_material` 的实现类型（`aluminum_foil`, `copper_foil`, `lithium_carbonate` 等）全部来自同一继承体系（`raw_materials → battery_raw_materials`），接口并未提供继承之外的新价值。

在此场景中，继承已覆盖接口的功能，导致该示例无法体现接口类型的核心价值。

## Palantir Interface 与继承的区别

| 维度 | 继承（抽象父类） | 接口（Interface） |
|---|---|---|
| 关系性质 | 严格的 is-a 层级关系 | 跨体系的 has-capability 契约 |
| 适用范围 | 同一继承树内 | 可被不同继承树上的类型实现 |
| 属性机制 | 子类直接继承父类属性 | 各实现类型需映射（mapping）到自己的本地属性 |
| 多实现 | 单一父类继承 | 一个类型可实现多个接口 |
| 典型场景 | 分类层级，共享通用属性 | 横切关注点，多态查询 |

参考 Palantir 官方示例：
- `Facility` 接口 → `Airport`、`ManufacturingPlant`、`MaintenanceHangar` 分别实现
- `Employable` 接口 → `Employee`、`Contractor`、`Consultant` 分别实现

## 当前体系中的继承树

```
raw_materials ─── battery_raw_materials ──┬── aluminum_foil
                                          ├── copper_foil
                                          ├── lithium_carbonate
                                          ├── lithium_hexafluorophosphate
                                          ├── lithium_iron_phosphate
                                          ├── ternary
                                          ├── diaphragm
                                          └── ...

components ────── battery_cell, motor, ...

composition_item ── cathode_material_composition_item, ...

company_entity (独立)
```

## 推荐的接口示例方案

### 推荐方案：`可溯源` (Traceable) ⭐

横切概念：需要对批次、来源做追溯的实体。该方案覆盖三种不同继承树上的类型。

| 接口属性 | 类型 | 必填 | 三元映射 | 电芯映射 | 公司映射 |
|---|---|---|---|---|---|
| `batch_number` | string | 否 | → (本地字段待定) | → serial_number | → registration_no |
| `supplier` | string | 否 | → manufacturer | → supplier_name | → chinaname |
| `production_date` | date | 否 | → (本地字段待定) | → manufacture_date | → foundation_date |

**优势：**
- 跨三种不同继承树，清晰展示接口与继承的区别
- `supplier` 在各类型映射到完全不同的本地字段，体现 mapping 机制
- 供应链追溯在新能源行业有实际业务价值

### 备选方案 1：`可定价` (Priced)

| 接口属性 | 碳酸锂 | 电芯 | 公司 |
|---|---|---|---|
| `current_price` | 行业报价 | unit_cost | 营收/市值 |
| `price_unit` | 元/吨 | 元/个 | 亿元 |
| `price_date` | 报价日期 | 成本核算日期 | 财报日期 |

**说明：** 需要对业务表补充价格字段，当前数据基础有限。

### 备选方案 2：`含碳排` (CarbonFootprint)

**说明：** 符合新能源行业方向，但当前无碳排基础数据，实施周期较长。

## 建议

先采用**方案一（可溯源）**实现，替换现有的 `if_raw_material` 示例。实施步骤：
1. 创建新接口定义（属性、约束）
2. 在目标对象类型的业务表中补充缺失的映射字段
3. 建立属性映射（mapping）
4. 清理旧的 `if_raw_material` 接口及映射
